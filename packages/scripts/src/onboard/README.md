# 项目初始化

在仓库根目录运行 `pnpm onboard`，依次完成四个阶段：

1. 安装依赖：执行 `pnpm install`。
2. 初始化环境：执行 `pnpm --filter xbd-mp-env run env:init`。没有应用时成功结束此阶段；已有 `config.ts` 的应用保持不变，缺失时按 `defaultEnv` 生成。
3. 准备工具库产物：按公开入口检查 `xbd-utils`，缺失时构建并复查。
4. 准备组件产物：检查 `xbd-miniprogram` 的必要分发文件，缺失时执行 `pnpm build:c --force` 并复查。

公共产物齐全时跳过对应构建；检查不比较源码时间戳，修改源码后仍需主动构建或开启监听。
各阶段显示编号与用时，任一阶段失败后不进入下一阶段，并以非零状态退出。

## 失败重试与中断

修复错误后重新运行 `pnpm onboard`，无需清理已有配置或齐全的公共产物。
初始化先校验所有待生成应用的环境配置，校验失败时不开始写入；写入期间若部分应用失败，已完成的应用会保留，再次运行时跳过。

按 Ctrl+C 或发送 SIGTERM 会停止后续阶段，并尝试终止当前命令的进程树；中断以非零状态退出。
已完成的阶段不会回滚。初始化写入失败时会尝试清理本次创建的 `config.ts`，若清理失败会报告错误，重试前应核查该文件。

## 组件预览与应用接入

`onboard` 只准备公共产物，不生成完整组件预览工程。
需要预览时再运行 `pnpm build:ce`，然后在微信开发者工具中导入根目录 `_example/`，按需选择自己的 AppID 或测试方式。

自建应用需单独导入微信开发者工具并执行“工具 → 构建 npm”。
仓库不附带业务应用；环境配置接入见 [mp-env 说明](../../../mp-env/README.md)。
